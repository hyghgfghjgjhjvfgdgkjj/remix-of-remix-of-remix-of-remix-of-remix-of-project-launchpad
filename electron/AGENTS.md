- `electron/` is a standalone desktop UI (`renderer/` HTML/CSS/JS, frameless window, own skeleton, own custom video player); catalog data comes from the active site's `/api/public/desktop/*` via IPC, cached per path in userData. Account/checkout uses only the isolated desktop-themed `/desktop-account` screen, never ordinary website pages. Why: keep all website navigation and promotions out of the app.
- Sign-in: `/desktop-account?action=google` starts the site's Google client directly, waits for profile phone verification, then origin-scoped IPC returns the Firebase session to the desktop. Access checks (`account-rules.cjs`) use server HTTP Date time (immune to wrong PC clocks), verify Firestore HTTP/error responses before updating `sub.json`, recognize verified owner-admin claims from Google's `id_token` plus assigned `user_roles`, and re-check on window close/focus/play. Why: wrong PC clocks and Firestore 429 quota days were falsely wiping active subscriptions and admin status.
- Downloads use Electron's download manager (pause/resume/cancel) saving to Videos/Movie max. Sidebar/tiles use generated 3D icons `renderer/ic-*.png`.
- Windows release = one NSIS setup (`build/installer.nsi`, built with `nix shell nixpkgs#nsis -c makensis` after @electron/packager) with desktop-shortcut + launch checkboxes; uploaded to public R2 and linked from the Install button. Why: user wants a single setup .exe, not a zip.
- Sign-in is an in-app float (Firebase email/password via identitytoolkit REST in main); Google still uses the account window. A wrong PC clock (ERR_CERT_DATE_INVALID) is tolerated only for our own hosts with one gentle notice. Why: user wants app-styled login and no blocking clock errors.
- Plans use the existing SubscribeModal on `/desktop-account?action=plans` with a live Firebase plans override and app theme; all existing methods, currency conversion and confirmation watchers are reused. Missing prices fail closed, never substitute defaults. Why: desktop prices and activation must not drift from the verified website flow.
- Downloads match each Electron DownloadItem by its original URL chain and use unique filenames. Why: out-of-order simultaneous requests must not swap controls or overwrite files.
- Home shows Luo/Teso uploaded rows (`/uploads/<lang>`, cached 10 min) under the hero; Trending uses MovieBox's real trending list. Website picks desktop vs phone download by user agent, never window width.
- Setup asks for administrator rights and installs to Program Files (per-machine shortcuts, HKLM uninstall). Why: user wants the setup to start with admin access. SmartScreen warning only goes away with a paid code-signing certificate.
- Luo/Teso rows: server caches non-empty lists in memory + Worker edge cache (`no-store` when empty) and handles `title/up-<id>` series/episodes; the desktop app falls back to direct Firestore REST and never overwrites a saved non-empty list with an empty one. Why: Firestore 429 quota days and missing series/legacy field mappings hid Luo uploads.
